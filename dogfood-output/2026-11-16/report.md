# research-tree 产品体验报告（2026-11-16）

范围：本地 WebUI 及服务端，独立空工作区。浏览器使用 agent-browser 0.31.1，视口 1280×720。先以未配置 key 的真实启动状态体验；涉及模型的完整链路会标明模拟或无法验证。测试任务：小型医院 AI 病历摘要试点，要求风险报告、人类文档、agent 计划和合成数据 demo。

## 发现

### ISSUE-001 · P1 · 无密钥发送后引导文字指向不存在的入口
- 复现：创建研究，在对话框输入任务并发送。
- 实际：错误提示要求点击左侧「pi 已就绪」，但左侧实际按钮为「未配置 key」。原文已保留在对话和输入框中，下一步应点哪个入口不够明确。
- 期望：提示直接引用当前可见的「未配置 key」入口；提交前可以预告缺少密钥，避免用户先写长消息后才遇到错误。
- 证据：[截图](screenshots/no-key-chat.png)。

### ISSUE-002 · P1 · 对话输入旁“自动”分类与研究执行模式易混淆
- 复现：打开对话输入左侧的「自动」下拉。
- 实际：选项为「自动、偏好、主张、猜测、岔路」，没有说明这是用户消息分类；从产品视角像研究执行模式，尤其未来加入轻量/平衡/深度后更易混淆。
- 期望：标注“消息类型/自动识别”，研究模式放在研究启动与仪表盘中，并解释其成本及质量取舍。
- 证据：[截图](screenshots/message-type-menu.png)。

### ISSUE-003 · P1 · 成功发送后输入框仍保留同一文本
- 复现：在配置好的隔离模拟模型环境，发送“约束已明确……请生成确认导图”。
- 实际：对话区已经出现用户消息、助手回复和“生 成”入口，但输入框仍是刚发送的全文且发送按钮可再次点击。重复操作容易制造重复 turn 与费用。
- 期望：成功提交后清空输入；失败时保留并明确提供“重试”而不是普通发送。需在真实模型环境复核时序。
- 证据：[截图](screenshots/chat-success.png)。

### ISSUE-004 · P0 · 明显无关的搜索命中仍让阶段标记 complete
- 复现：确认导图进入研究画布，打开“探索｜任务背景”节点。
- 实际：节点显示 complete、产出 5 来源；五条来源分别涉及游戏剧情、宇宙探索、航天路线图、背景音和太空探索，与“小型医院病历摘要试点”无关。固定模拟综合文本明确说“资料不足，不能得出真实结论”，阶段仍显示完成，随后还自动创建了汇总节点。
- 影响：用户无法把 complete 当作已解决问题；系统继续检索和汇总，造成无效消耗。该观察来自模拟综合输出加真实检索结果，尚未测真实模型质量。
- 期望：将检索完成、证据相关性、结论质量和阶段收口分开；无关来源不得满足完成条件；停止无收益循环并列出证据缺口。
- 证据：[节点与来源截图](screenshots/research-artifact.png)。

### ISSUE-005 · P0 · 研究中没有停止和预算控制入口
- 复现：确认导图后进入画布，观察顶部操作和运行中的节点。
- 实际：只有“回到对话”“思维导图”“刷新”“继续（GO）”及“冻结裁决”，没有停止/暂停研究或设置上限的操作；也没有 token、费用、调用次数和剩余预算。运行中三个节点并发检索、综合后自动进入汇总。
- 期望：任务级立即停止、持久停止状态、服务端预算上限和任务级消耗仪表盘。冻结裁决不能代替停止。
- 证据：[研究启动截图](screenshots/research-start.png)。

### ISSUE-006 · P1 · 汇总节点名称只代表首分支
- 复现：待三个“限制条件、任务背景、调研目标”节点完成，观察汇总节点。
- 实际：汇总被命名为“汇总｜限制条件”，看起来只汇总一个分支，虽然依赖为 3；该节点又进行一次检索并报告 5 个来源。
- 期望：汇总节点表达完整研究目标与覆盖范围；解释为何追加检索，并展示各导图分支的已回答与缺口。
- 证据：[研究产物截图](screenshots/research-artifact.png)。

### ISSUE-007 · P1 · 画布首次布局使节点受顶部工具栏遮挡
- 复现：进入研究画布，尝试点击左上第一个节点“探索｜限制条件”。
- 实际：agent-browser 报节点点击点被 `.research-toolbar` 覆盖；截图可见节点边缘贴在工具栏下，点击第二个节点才成功。
- 期望：适配工具栏和 Console 占用后的画布可视区域，首次 fit view 保证所有节点可点击。
- 证据：[研究启动截图](screenshots/research-start.png)。

### ISSUE-008 · P0 · 无有效证据仍可签署 GO，且没有约定交付物验收
- 复现：在 ISSUE-004 的资料不足状态，保持默认“继续（GO）”，点击“冻结裁决”并“签署并提交”。
- 实际：仅有“版本 append-only”通用提示，无证据质量、导图覆盖、未解决问题、交付物或 demo 清单；系统接受 GO 并提示 v0 已提交。页面仍留在调研画布，与弹窗承诺的“回到对话阶段”不一致。
- 期望：签署前呈现导图和交付约定的覆盖矩阵、来源与缺口；必需项未满足时阻止“完成式 GO”或明确按部分交付处理；提交后导航与提示一致。
- 证据：[确认弹窗](screenshots/freeze-go-dialog.png)、[提交后页面](screenshots/freeze-result.png)。

### ISSUE-009 · P1 · 产物抽屉只有摘要与外链，无法查看保存的原始证据
- 复现：打开任一已完成节点的产物抽屉。
- 实际：抽屉列出一段发现及搜索结果标题/片段/外链；没有网页快照、原始文档或图片、采集时间、证据 ID、引用位置与可下载原件的入口。仅从浏览器无法证明后端完全没有保存原件，但当前产品无法让用户核验。
- 期望：证据库独立呈现原件、提取内容和结论，并从主张跳转到可定位的原始材料；快照缺失要明示。
- 证据：[产物抽屉](screenshots/research-artifact.png)。

### ISSUE-010 · P2 · 搜索无匹配时侧栏清空，但当前任务内容仍显示且标题变成产品名
- 复现：在某任务对话中搜索不存在的项目名，等待搜索完成。
- 实际：侧栏无任务，主区仍显示原任务对话，顶部却变成“research-tree”，没有“无匹配”说明；用户难以判断当前上下文和搜索结果的关系。
- 期望：空结果提示、保留当前任务标题或明确显示“正在查看筛选外的任务”。
- 证据：[截图](screenshots/search-after-debounce.png)。

### ISSUE-011 · P0 · 390px 手机视口主内容被侧栏挤到只剩一列字
- 复现：在已打开的任务上将浏览器视口设为 390×844。
- 实际：侧栏仍占约 260px，主区标题被压成逐字竖排，对话无法正常阅读。手动收起侧栏后才基本可用；初始状态不能完成核心任务。
- 期望：窄屏默认收起或浮层展示项目导航，主内容宽度优先；进入画布时同样保证控制与节点可用。
- 证据：[初始截图](screenshots/mobile-chat.png)、[手动收起后](screenshots/mobile-chat-collapsed.png)。

### ISSUE-012 · P1 · 返回研究画布后 Console 历史消失
- 复现：运行完成后从画布返回对话，再打开“调研画布（报告已冻结）”。
- 实际：阶段仍显示 complete，但底部 Console 只剩“── 引擎事件流（实时）──”，此前检索、增益和汇总记录不再可见；用户无法在 UI 复核执行经过。
- 期望：从持久事件恢复任务级历史和时间顺序，明确区分历史与实时事件。
- 证据：[重新打开画布截图](screenshots/research-reopen-console.png)，对照 [运行中截图](screenshots/research-start.png)。

### ISSUE-013 · P1 · 手机画布顶部操作横向溢出
- 复现：将视口设为 390×844，收起侧栏后打开调研画布。
- 实际：工具栏中标题竖排，裁决选择和“冻结裁决”被挤出可见区域；画布虽能显示节点，但无法顺畅完成裁决操作。
- 期望：窄屏将工具栏分行或折叠为清晰操作菜单，裁决和停止始终可达；节点和抽屉适配视口。
- 证据：[手机画布截图](screenshots/mobile-research.png)。

### ISSUE-014 · P2 · 导图大纲的辅助树级别与可视层级不一致
- 复现：在导图页点击“大纲”，检查浏览器可访问性快照。
- 实际：root、二级分支及叶子节点全部暴露为 `treeitem level=1`，虽然画面上有缩进。屏幕阅读器无法按真实层级理解导图。
- 期望：树项按实际层级暴露，并支持键盘展开/收起及编辑。
- 证据：[大纲截图](screenshots/mindmap-outline.png)；agent-browser 的 `snapshot` 输出显示全部 level=1。

## 覆盖与限制

已用浏览器体验：新研究创建、无密钥错误与设置入口、对话发送和消息类型、导图生成/大纲/节点编辑入口/确认、研究画布与节点产物、人工裁决冻结、项目搜索、返回与重开、390px 窄屏。项目重命名、归档和删除入口已看到，未把破坏性的管理操作作为本次核心链路；文档导入、图片导入、网页快照、研究模式、预算配置、停止及约定交付物入口在所见产品中不可达或缺失。

模型回答和增益由隔离的固定模拟 runner 提供，未使用真实付费模型；搜索命中由当前服务实际返回。报告证明可见 UI 与流程缺陷，不代表对真实模型质量、实际费用、后台持久化或网页原件存储作了完整审计。未使用真实医疗数据。浏览器 Console/JS errors 检查未发现额外错误。受限于环境和成本，未做真实模型长跑与多设备矩阵。
