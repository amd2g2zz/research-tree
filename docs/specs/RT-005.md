# RT-005: Bounded Research Work Items

## Status

Accepted for implementation. This specification is the executable scope for
GitHub issue #5 and consumes RT-004 Blueprint Targets.

## Public API

```python
items = WorkItemPlanner(store).plan(
    round_id="round-001",
    blueprint_target=target,
    work_item_ids={"slot-architecture": "work-architecture"},
    mode="dependency_respecting",
)
deferred = WorkItemStatusService(store).update(
    round_id="round-001",
    work_item=item,
    blueprint_target=target,
    status="deferred",
    reason="The target no longer needs this decision this round.",
)
```

`WorkItemCompiler` is also public for explicit exceptional work. It requires
an exact Blueprint Target and one slot id, and rejects a closed slot unless an
`exception_reason` is recorded.

## Work Item Contract

```python
{
    "id": "work-architecture",
    "round_id": "round-001",
    "blueprint_target_id": "blueprint-target",
    "decision_slot_id": "slot-architecture",
    "intent_hypothesis_ids": ["intent-agent"],
    "kind": "repository_analysis",
    "scope": "the slot question",
    "exclusions": "do not close the decision or add unrelated scope",
    "decision_change_reason": "which option or closure condition this finding can change",
    "depends_on": [],
    "methods": ["repository_inspection"],
    "budget": {"tool_calls": 8, "time": "bounded"},
    "completion_rule": "return a Finding Pack or explain unavailable evidence",
    "expected_finding_pack": {
        "observations": "atomic observations with anchors and limitations",
        "option_effects": "support, contradict, or limit each option",
        "implementation_implications": "repository or greenfield consequence",
        "remaining_uncertainties": "explicit unresolved evidence"
    },
    "status": "ready|planned|running|complete|cancelled|deferred",
    "status_reason": null
}
```

Only `open` and `researching` slots are normal planning candidates. A closed
slot (`selected`, `conditional`, `deferred`, or `blocked`) requires a nonempty
exception reason for an explicit work artifact. Work completion does not change
the slot status.

## Deterministic Planning

- `dependency_respecting` retains dependencies between emitted work for active
  upstream slots. A work item is `ready` when it has none, otherwise `planned`.
- `serial` uses the same stable topological order and adds the preceding emitted
  work item as a dependency, forming one deterministic chain.
- IDs must map exactly to active target slots. The planner sorts equally ready
  slots by id, so input list order does not change output.

## Status Revisions

`WorkItemStatusService.update` accepts only `cancelled` or `deferred` and a
nonempty reason. It retains the original bounded contract, links the previous
Work Item revision and current Blueprint Target, and never overwrites history.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| deterministic target plan | stable topological output, dependency graph, bounded contract, and target parent refs |
| serial plan | same order becomes an explicit one-item-at-a-time chain |
| invalid slot | missing, closed without exception, and unrelated hypothesis fail before append |
| exceptional closed work | nonempty exception reason is preserved and status is deferred |
| lifecycle | cancellation and deferral append revisions with reasons and exact previous refs |
