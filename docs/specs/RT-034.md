# RT-034: Atomic Feedback Successor Creation

## Status

Accepted for implementation. This specification implements GitHub issue #34.

## Problem

`FeedbackRoundService.start_successor` previously created the successor round
and several artifacts before the Intent Model and Working Brief compilers had
validated all supplied data. A compiler rejection therefore left a partial
round that prevented a corrected request from reusing its intended round id.

## Contract

- A rejected successor request must not persist a successor round, successor
  artifact, or predecessor supersession record.
- All request validation, carried-input copying, Intent Model compilation,
  Working Brief compilation, lineage creation, strategy creation, and
  supersession creation must succeed as one preflight before the real store is
  changed.
- The preflight uses an isolated copy of the current run store. It has the same
  persisted predecessor references as the real store, so it exercises the
  normal validators and compiler paths without adding validation-only APIs.
- Once preflight succeeds, the same request is written to the real store. A
  corrected retry may use the same successor round id after any rejected
  request.

## Acceptance Cases

| Rejected input | Required observable result |
| --- | --- |
| malformed Intent Model analysis | no successor round; corrected retry succeeds |
| incomplete Working Brief input roles | no successor round; corrected retry succeeds |
| malformed material conflicts | no successor round; corrected retry succeeds |
| a later Working Brief compiler validation failure | no successor round; corrected retry succeeds |
