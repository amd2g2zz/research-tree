# RT-004: Blueprint Targets and Decision Maps

## Status

Accepted for implementation. This specification is the executable scope for
GitHub issue #4 and depends on RT-002 Input Ledger artifacts and RT-003
Working Briefs.

## Public API

```python
target = BlueprintTargetCompiler(store).compile(
    round_id="round-001",
    target_id="blueprint-target",
    working_brief=brief,
    slots=[...],
    change={
        "kind": "initial",
        "reason": "Map the implementation decisions implied by the brief.",
        "from_slot_ids": [],
        "to_slot_ids": ["slot-architecture"],
    },
)
```

The immutable artifact envelope supplies target identity and revision. The
payload contains `brief_id`, `intent_model_id`, normalized slots, and the
recorded change. A later artifact revision has an exact parent ref to the
previous Blueprint Target and the same exact Working Brief / Intent Model
lineage.

## Decision Slot Contract

Each slot has these fields:

```python
{
    "id": "slot-architecture",
    "kind": "architecture",
    "question": "Which isolation boundary supports the first implementation?",
    "intent_hypothesis_ids": ["intent-agent"],
    "priority": "P0",
    "impact": "high",
    "uncertainty": "high",
    "irreversibility": "high",
    "constraints": [{"kind": "input", "ref": "input-brief", "statement": "..."}],
    "alternatives": ["isolated-worker", "in-process"],
    "repository_touchpoints": [{"path": "src/agent.py", "symbol": "run"}],
    "greenfield_assumptions": [],
    "depends_on": [],
    "evidence_standard": "repository inspection plus a bounded spike",
    "validation": {"kind": "spike", "oracle": "worker process handles one fixture"},
    "closure_rule": "select, conditionally select, defer with fallback, or block",
    "status": "open",
    "bounded_research_need": "compare the two isolation choices against repository boundaries",
    "fallback": "retain the current boundary until the decision closes",
}
```

- `intent_hypothesis_ids` must be visible in the exact Intent Model referenced
  by the Working Brief.
- `constraints.kind` is `input`, `repository`, or `assumption`. Input refs must
  be selected Brief inputs; repository refs use a `path` or `path:symbol`
  anchor from the recorded baseline.
- `repository_touchpoints` must resolve to the exact selected repository
  baseline. Without any selected repository baseline, they must be empty and
  `greenfield_assumptions` must be nonempty.
- All slots need a question, at least two distinct alternatives, evidence
  standard, validation oracle, closure rule, and fallback. An `open` or
  `researching` P0 additionally needs a nonempty `bounded_research_need`.
- Dependencies must refer to another slot and form an acyclic graph.

## Controlled Revisions

`change` has exact keys `kind`, `reason`, `from_slot_ids`, and `to_slot_ids`.
The compiler validates the before/after id sets:

| Kind | Required change |
| --- | --- |
| `initial` | no previous target; all current ids appear in `to_slot_ids` |
| `add` | no source ids; targets are newly added ids |
| `remove` | source ids were removed; no target ids |
| `split` | one removed source becomes at least two new targets |
| `merge` | at least two removed sources become one new target |
| `reprioritize` | same source/target ids; only priority changes |

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| repository-backed target | exact brief, model, repository anchor, and P0 slot persist and rehydrate |
| P0 ownership and closure | missing intent basis, alternatives, research boundary, validation, or fallback fails before append |
| anchor and greenfield boundaries | unknown repository anchor fails; no-repository target needs an explicit assumption |
| dependencies | unknown and cyclic dependencies fail before append |
| controlled revisions | add, split, merge, reprioritize, and remove append target revisions with previous-target refs |
