# RT-015: Verified OpenSpec Export

## Status

Accepted for implementation. This specification implements GitHub issue #35.

## Problem

The Technical Research Package retains a delivery-time readiness projection, but
that projection is not proof that `ReadinessVerifier` evaluated the exact
package revision. A caller can therefore compile a package with optimistic
readiness data and export a normal OpenSpec change without a persisted
verification result.

## Contract

`OpenSpecExporter.export(..., draft=False)` must resolve a persisted
`readiness-record` in the requested round whose `technical_package_ref` and
parent reference identify the exact persisted Technical Research Package
revision being exported. The readiness record must validate and its delivery
projection must satisfy the normal export readiness gates.

If there is no matching record, if the matching record is malformed, or if its
gates do not permit normal export, the exporter fails before creating an output
directory. A readiness record for another package revision never authorizes the
current package.

`draft=True` remains an explicit caller-selected projection. It renders the
package's visible blockers and does not require a passing readiness record.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| unverified package | normal export rejects without creating a directory |
| exact verified package | normal export succeeds |
| stale readiness record | a later package revision cannot use it and normal export rejects |
| explicit draft | export succeeds with a draft warning even without readiness evidence |
