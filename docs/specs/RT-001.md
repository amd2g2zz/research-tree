# RT-001: Run-Scoped Runtime Foundation

## Status

Accepted for implementation. This specification is the executable scope for
GitHub issue #1.

## Public API

```python
store = RunStore(root)
round_record = store.create_round(round_id=None, parent_round_id=None)
revision = store.append_artifact(
    round_id,
    artifact_id,
    kind,
    payload,
    parent_refs=(),
)
snapshot = store.load_round(round_id)
```

`root` is required. `round_id` and `artifact_id` are stable identifiers, not
paths. `parent_refs` are exact `(round_id, artifact_id, revision)` references
to existing artifacts in the same store.

## Persistence Contract

```text
<root>/
  rounds/<round-id>/
    round.json
    artifacts/<artifact-id>/<six-digit-revision>.json
    events/<event-id>.json
```

`round.json` is written once when the round is created. Each artifact file is
a complete versioned envelope containing the round id, artifact id, revision,
kind, parent references, created time, JSON payload, and SHA-256 digest of its
canonical content. Each create/append operation records a separate lineage
event. No file is updated in place.

The in-memory `RoundSnapshot` is a projection of those files. Reopening a
store creates no hidden cache and must produce the same round identity,
artifact revisions, parent references, and event identifiers.

## Validation Contract

- IDs match `^[a-z][a-z0-9-]{0,63}$`.
- Artifact payloads are JSON objects composed of JSON values only.
- A child round requires an existing parent round.
- A parent artifact reference requires the exact stored revision.
- Existing round files and artifact revision files are never overwritten.
- Malformed or hash-mismatched persisted data fails on load.

## Required Behavior

1. Creating two distinct rounds in one explicit store root creates separate
   directories and leaves each snapshot unaware of the other round's
   artifacts.
2. Appending the same artifact id twice creates revisions `1` and `2`; mutating
   the caller's original payload after the first append cannot change revision
   `1`.
3. Reconstructing through a new `RunStore(root)` returns the same ids,
   revisions, parent references, and lineage events.
4. The CLI supports:

   ```text
   python -m research_tree create-round --store <path> [--round-id <id>]
   python -m research_tree show-round --store <path> --round-id <id>
   ```

5. Runtime source has no dependency on the retired research state model.

## Module Boundaries

| Module | Responsibility | Excludes |
| --- | --- | --- |
| `domain` | immutable records, JSON conversion, structural validation | product-policy decisions |
| `storage` | directory layout, atomic new-file writes, replay | intent/strategy logic |
| `application` | create/load/append use cases | CLI parsing and future domain workflows |
| `ports` | typed protocols for intake, intent, strategy, research, convergence, delivery, verification | concrete adapters |
| `cli` | explicit command boundary and JSON output | hidden defaults/global roots |

## Test-First Acceptance Cases

| Test | Expected result |
| --- | --- |
| two-round isolation | each round sees only its own artifacts and files |
| immutable revisions | earlier payload/hash remains unchanged after a later revision |
| rehydrate and lineage | fresh store instance reconstructs artifact and parent links |
| rejected unsafe input | bad ids, missing parent refs, and non-JSON payload fail without overwrite |
| explicit root | no default workspace path is accepted |
| CLI workflow | create then show returns the persisted round snapshot |
