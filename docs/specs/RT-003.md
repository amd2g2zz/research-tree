# RT-003: Traceable Intent Models and Working Briefs

## Status

Accepted for implementation. This specification is the executable scope for
GitHub issue #3 and extends the RT-001 store and RT-002 Context Pack intake.

## Public API

```python
model = IntentModelCompiler(store).compile(
    round_id="round-001",
    intent_id="intent-model",
    context_bundle_ids=("input-context",),
    input_ids=("input-brief", "input-note"),
    analysis={...},
)
brief = WorkingBriefCompiler(store).compile(
    round_id="round-001",
    brief_id="working-brief",
    intent_model=model,
    ...,
)
recommendation = QuestionPolicy().recommend(model)
```

`analysis` is supplied by a deterministic adapter or test fixture. The
compiler validates and persists it; it does not claim to infer user intent from
keywords. Its signals must cite selected input ids and every hypothesis must
cite signals, label its status, confidence, decision consequence, and
validation path.

## Intent Model Contract

- Artifact kind is `intent-model`. The immutable artifact envelope carries
  `id`, `round_id`, and `revision`; its payload carries the domain fields from
  the product contract, so no duplicated revision can diverge under concurrent
  appends.
- Exactly one `leading` hypothesis is required; material alternatives remain
  `viable` or `needs_user_input`, never merged into the leading interpretation.
- Signals are observed material and hypotheses are explicit inferences.
- All signal refs, driver refs, bundle ids, and selected input ids resolve to
  exact RT-002 ledger artifacts in the target round.
- Invalid contract input leaves no new artifact revision.

## Working Brief Contract

- Artifact kind is `working-brief`; it has exact parent refs to the Intent
  Model and selected input revisions.
- It records triggers, selected input roles, conflicts, leading hypothesis,
  viable alternatives, constraints, assumptions, technical outcome, and
  delivery targets. Selected inputs and bundles must be an exact-revision
  subset of the Intent Model's interpreted context; new material requires a
  new Intent Model first.
- Default delivery targets are Technical Research Package and Human Brief;
  OpenSpec is `false` until an explicit later exporter is called.

## Question Policy

`QuestionPolicy` returns `None` by default. It returns one nonblocking
recommendation only when an unresolved interpretation is consequential,
non-recoverable, and cannot be ranked from available evidence. It never blocks
compilation or changes a round status.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| conflicting material | separate signals and leading/viable hypotheses persist without a blended goal |
| invalid anchor | unknown input or signal ref fails before a model is written |
| partial ambiguity | model and brief persist with assumptions and viable alternatives |
| question exception | only the three-condition ambiguity produces one nonblocking recommendation |
| brief traceability | roles, conflicts, exact intent ref and default deliveries survive rehydration |
| immutability | later revisions preserve prior model/brief content and parent refs |
