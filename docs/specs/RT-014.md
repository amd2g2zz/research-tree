# RT-014: Strategy-Selected Assurance Adapters

## Status

Accepted for implementation. This specification implements GitHub issue #14 on
top of RT-005 bounded work, RT-006 immutable findings and decisions, RT-008
readiness, and RT-009 persisted Research Strategies.

## Outcome

Research Strategies may opt into source acquisition, primary-source validation,
evidence review, and provenance-integrity checks for a particular Decision Slot.
The cost and outcome of those checks remain local to that decision. Ordinary
research rounds retain the existing P0 path without an assurance plan or an
adapter invocation.

## Public API

```python
selection = AssuranceStrategySelector(store).select(
    round_id="round-001",
    selection_id="assurance-selection-001",
    strategy=strategy,
    blueprint_target=target,
    policies=[
        {
            "decision_slot_id": "slot-isolation",
            "risk_tier": "high",
            "evidence_standard": "high_assurance",
            "decision_value": "high",
            "failure_mode": "block",
            "selection_reason": "The isolation choice gates a security boundary.",
        }
    ],
)

result = AssuranceAdapterRunner(store).run(
    round_id="round-001",
    evidence_id="assurance-evidence-001",
    selection=selection,
    decision=decision,
    source={
        "locator": "https://example.test/security-guide",
        "version": "published-2026-07-31",
        "extraction_boundary": "sections 2 through 4",
        "applicability": "the selected worker-isolation decision",
    },
    adapters=AssuranceAdapterSet(...),
)
```

`AssuranceStrategySelector` derives the selected adapter kinds from each
strategy policy:

| Evidence standard | Adapter kinds |
| --- | --- |
| `ordinary` | none |
| `primary_source` | source acquisition, primary-source validation; add evidence review when risk or decision value is `high` |
| `high_assurance` | source acquisition, primary-source validation, evidence review, provenance integrity |

Every policy records its risk tier, evidence standard, decision value, failure
mode, and reason. The selector derives the adapter set from all three: the
evidence standard establishes the baseline, and high risk or high decision
value upgrades primary-source work with an applicability review. It is an
immutable `assurance-adapter-selection` artifact
with exact persisted Research Strategy and Blueprint Target parent references.
It does not rewrite the narrow RT-009 `research-strategy` payload.

## Adapter Boundary

The public ports are intentionally small and separately typed:

- `SourceAcquisitionPort.acquire(request)`;
- `PrimarySourceValidationPort.validate_primary_source(request)`;
- `EvidenceReviewPort.review(request)`; and
- `ProvenanceIntegrityPort.verify_integrity(request)`.

Selected adapters receive a structured request and return a structured result.
An adapter result has a `passed` or `failed` status and a summary, and may
refine the source version, extraction boundary, or applicability. Missing a
selected adapter and an adapter exception are recorded as failed results, not
silently ignored.

## Provenance And Failure Contract

An `assurance-evidence` artifact records:

- the exact selection, strategy, target, and Decision Ledger revision it
  informs;
- source locator, version, extraction boundary, and applicability;
- every selected adapter's result;
- the evidence-review and integrity results; and
- a terminal `passed` or `failed` status.

The runner never edits a Finding Pack. A successful assurance result is a
separate, inspectable evidence artifact. On a failed result:

- `failure_mode="follow_up"` emits an immutable `assurance-follow-up` record
  scoped to the selected Decision Slot; or
- `failure_mode="block"` appends a new `decision-ledger-entry` revision with
  `status="blocked"`, preserving the previous decision and its findings.

An `assurance-resolution` artifact links the evidence result to the follow-up
or blocked Decision Ledger revision. No global gate, evidence DAG, snapshot
freeze, report workflow, or scheduler behavior is introduced.

## Invariants

- A selection accepts an empty policy list. It has no impact on ordinary work
  planning, finding compilation, delivery, or readiness verification.
- Each policy names one exact Decision Slot in the selected Blueprint Target;
  a slot can appear only once in a selection.
- The strategy, target, decision, selection, and all emitted artifacts must be
  exact persisted revisions in one round and share the same Working Brief.
- High-assurance policies may be selected only deliberately through the
  persisted strategy-selection artifact. They are never inferred globally from
  a source list or a P0 label.
- Adapter results cannot alter stored Finding Pack or prior Decision Ledger
  payloads. Blocking appends a revision with a reversal condition instead.
- The selected source metadata and outcome remain replayable after reopening a
  `RunStore`.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| ordinary strategy | empty policy selection leaves the existing P0 vertical path untouched |
| high-assurance success | all four selected adapter ports run; source version, extraction boundary, applicability, review, and integrity persist with exact decision lineage |
| failed integrity | a targeted follow-up artifact names only the affected Decision Slot and prior Finding Packs remain unchanged |
| failed review with block mode | a new immutable blocked Decision Ledger revision is emitted and linked to the failed assurance evidence |
| invalid policy or adapter result | validation fails before appending a partial selection or evidence artifact |
