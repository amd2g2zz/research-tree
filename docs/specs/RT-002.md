# RT-002: Context Intake and Repository Reconnaissance

## Status

Accepted for implementation. This specification is the executable scope for
GitHub issue #2 and extends RT-001 without changing its public store API.

## Public API

```python
from research_tree import InputIntakeService, RepositorySafetyPolicy, RunStore

store = RunStore(root)
store.create_round("round-intake")
intake = InputIntakeService(store, policy=RepositorySafetyPolicy())

brief = intake.ingest_text(
    round_id="round-intake",
    input_id="input-brief",
    kind="brief",
    content="Build an autonomous reverse-engineering agent.",
    origin_type="user",
    origin_locator="conversation:1",
    role="signal",
)
repository = intake.ingest_repository(
    round_id="round-intake",
    input_id="input-repository",
    repository_root=repository_path,
    origin_type="workspace",
    role="baseline",
)
bundle = intake.create_context_bundle(
    round_id="round-intake",
    input_id="input-context",
    member_input_ids=("input-brief", "input-repository"),
    origin_type="user",
    origin_locator="conversation:1",
    role="baseline",
)
```

All methods return the immutable `ArtifactRevision` written through `RunStore`.
`input_id` follows the RT-001 identifier rule. `kind`, `origin_type`, `role`,
and `grouping` are constrained to the values in the product contract.

## Input Ledger Artifact Contract

Each artifact has `kind == "input-ledger-entry"` and a payload with the base
fields from `references/product-contracts.md`:

```jsonc
{
  "id": "input-brief",
  "kind": "brief",
  "origin": {"type": "user", "locator": "conversation:1"},
  "revision": {"branch": null, "commit": null, "sha256": "...", "observed_at": "..."},
  "read_scope": "full text",
  "role": "signal",
  "member_input_ids": [],
  "grouping": "none",
  "used_by_rounds": ["round-intake"],
  "material": {"kind": "inline-text", "content": "..."}
}
```

Repository entries replace `material` with `repository_baseline`. Context
Bundle entries have `kind == "context_bundle"`, a nonempty ordered
`member_input_ids`, `member_refs` containing the exact selected revisions, and
the same refs as `parent_refs` on their artifact envelope. A bundle never
rewrites or merges member artifacts.

## Repository Baseline Contract

```jsonc
{
  "repository_root": "absolute canonical local path",
  "read_scope": ["."],
  "revision": {"branch": "main", "commit": "...", "dirty": false, "sha256": "...", "observed_at": "..."},
  "anchors": [{"path": "src/app.py", "symbol": "main"}],
  "facts": [{"category": "entry_point", "anchor": {"path": "src/app.py", "symbol": "main"}, "observation": "candidate entry point by filename"}],
  "unreadable": [{"path": ".env", "reason": "secret"}]
}
```

All anchor paths are repository-relative and contain no `..`. Facts may be
`path`, `source`, `symbol`, `entry_point`, `behavior`, `interface`,
`dependency`, `test`, `deployment`, or `change_surface`; they are observations,
not architecture recommendations. The repository revision uses Git metadata
when available and a SHA-256 fingerprint over safely read files.

## Safety Contract

- Intake is read-only with respect to the repository and never executes its
  code, test suite, build, hooks, or user-supplied commands.
- A repository root that is itself a symlink is rejected; accepted scope labels
  are repository-relative whenever they resolve inside the root.
- `include_paths` is constrained to the canonical repository root. Out-of-root
  and missing requests appear in `unreadable` and do not stop safe scopes.
- Secret paths, binary files, oversized files, scan-budget excess, excluded
  directories, symlinks, unreadable encodings, and nonregular files are never
  included as readable content. Their reason is persisted without content.
- Symlinks are never followed. Links escaping the root are `external_symlink`;
  links remaining inside it are `symlink_not_followed`.
- Re-ingesting an input id appends an artifact revision. A previously created
  Context Bundle continues to reference its original member revisions.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| independent material | brief, article and note are separate ledger artifacts with content hashes and input metadata |
| grouped conflict | a bundle preserves both conflicting member refs without synthetic content or authority |
| repository baseline | Git branch/commit and repository-relative anchors for source, symbol, dependencies, tests and deployment are stored |
| changed input | a second ingestion creates a new revision while the first stays unchanged |
| safe partial scan | unsafe paths are recorded with reasons while safe files still produce facts |
| scope boundary | `../outside` is not read and is recorded without failing safe repository intake |
| bundle validation | unknown, duplicate, or nested bundle members are rejected without writing a partial bundle |
