# RT-009: Feedback-Triggered Successor Rounds

## Status

Accepted for implementation. This specification implements GitHub issue #9 on
top of the immutable run store, Context Pack intake, Intent Models, Working
Briefs, Decision Ledger entries, and compiled deliveries.

## Problem

Feedback is new material about the requester's current intent. It must not
silently edit an earlier package, reinterpret old evidence as still accepted,
or turn normal research replanning into a user-round transition.

## Public API

```python
result = FeedbackRoundService(store).start_successor(
    prior_round_id="round-001",
    successor_round_id="round-002",
    feedback_input_id="input-feedback",
    feedback_text="Prioritize a local, inspectable workflow.",
    feedback_origin_locator="conversation:2",
    change_dimensions=("priority", "success_definition"),
    change_reason="The prior hosted direction no longer meets the requested demo.",
    safe_checkpoint="After the current finding-pack boundary.",
    candidates=(
        CandidateContext("candidate-input", prior_input, "reuse", "Still authoritative."),
        CandidateContext("candidate-decision", prior_decision, "overturn", "Rejected direction."),
    ),
    intent_id="intent-002",
    intent_input_ids=("input-feedback", "input-brief"),
    intent_analysis={...},
    context_bundle_id="context-002",
    context_member_input_ids=("input-feedback", "input-brief"),
    brief_id="brief-002",
    selected_input_ids=("input-feedback", "input-brief"),
    input_roles={"input-feedback": "primary", "input-brief": "context"},
    material_conflicts=(),
    working_interpretation="...",
    technical_outcome="...",
    strategy_id="strategy-002",
    strategy_summary="...",
    strategy_focus=("...",),
)

replan = FeedbackRoundService(store).record_same_round_replan(
    round_id="round-001",
    replan_id="replan-001",
    feedback_input_id="input-note",
    feedback_text="Keep the same target but spend less on one spike.",
    feedback_origin_locator="conversation:3",
    reason="Budget allocation changes, not the target.",
)
```

`CandidateContext` has a stable candidate id, one exact persisted predecessor
artifact, one disposition, and a non-empty rationale. `FeedbackRoundArtifacts`
returns the successor `RoundRecord`, feedback Input Ledger entry, copied inputs,
Intent Model, Working Brief, `research-strategy`, `feedback-lineage`, and the
predecessor `round-supersession` record.

## Successor Contract

- `change_dimensions` must explicitly name one or more of `target`, `priority`,
  or `success_definition`. The service does not infer a target change from
  silence, approval, or wording alone.
- A successor round gets a new Intent Model, Working Brief, and
  `research-strategy` artifact. The feedback itself is a `feedback` Input
  Ledger entry and is a selected Brief trigger.
- Every latest predecessor Input Ledger entry, Finding Pack, and Decision
  Ledger entry needs one explicit candidate disposition: `reuse`, `revalidate`,
  `downgrade`, `ignore`, or `overturn`. Extra predecessor artifacts may also be
  candidates. Missing disposition rejects before the successor round is
  created; no value defaults to reuse.
- `reuse`, `revalidate`, and `downgrade` predecessor non-bundle inputs are
  copied into the successor as new Input Ledger revisions with an exact
  predecessor parent ref. The source payload remains unchanged and the copied
  payload records only the successor in `used_by_rounds`. `ignore` and
  `overturn` remain available through `feedback-lineage`, but cannot be silently
  selected by the successor Brief.
- `feedback-lineage` keeps every exact predecessor ref, disposition, rationale,
  feedback ref, and the parent/new-root relationship. The successor Working
  Brief receives the same source-artifact-id-to-disposition map.
- A normal successor has `parent_round_id=prior_round_id`. When
  `overall_rejection=True`, the successor is a new root with
  `parent_round_id=None`; its lineage still makes the rejected predecessor
  inspectable.
- The predecessor receives an append-only `round-supersession` record after the
  supplied safe checkpoint. It records all latest active Work Items with
  `disposition="superseded"`, but does not overwrite Work Items, findings,
  decisions, deliveries, or the old round record. Work Item planning and
  portfolio scheduling read this overlay and reject normal new work for the
  superseded round.

## Same-Round Replanning

`record_same_round_replan` persists a feedback input and a
`same-round-replan` record in the current round. It creates no new round,
Intent Model, Working Brief, strategy, or supersession record. It is intended
for a bounded research or budget adjustment that does not change target,
priority, or success definition.

## Strategy Contract

The minimal `research-strategy` artifact is intentionally a small ownership
boundary until a dedicated strategy compiler exists. It contains exact parent
references to the successor Intent Model, Working Brief, and feedback lineage;
the changed dimensions; a non-empty summary; non-empty focus items; and the
fixed autonomous policy of asking only for non-recoverable decisions. It does
not schedule, execute, or reintroduce a global research DAG.

## Non-goals

- Do not derive intent with keyword rules or decide a disposition from prior
  approval, silence, or a default.
- Do not delete or overwrite predecessor artifacts, round records, findings,
  decisions, or deliveries.
- Do not treat routine same-round replanning as a new user round.
- Do not execute research, work items, repository code, readiness checks, or
  OpenSpec export.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| mixed successor context | reuse, revalidation, downgrade, ignore, and overturn survive in exact lineage and the new Brief while predecessor artifacts remain unchanged |
| active predecessor work | a safe-checkpoint supersession record names every active Work Item without overwriting it |
| old execution retry | Work Item planning and portfolio scheduling reject normal work after the supersession overlay |
| overall rejection | successor has no parent round but preserves predecessor candidate provenance |
| routine replan | only a same-round replan record and feedback input are appended; no successor Intent Model or Brief appears |
| implicit retention | omitting a required predecessor candidate rejects before a successor round is created |
