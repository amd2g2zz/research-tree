# RT-013: Explicit OpenSpec Delta Export

## Outcome

Expose OpenSpec only as a caller-invoked, downstream adapter for a persisted
Technical Research Package. The adapter emits a conventional OpenSpec change
directory and never becomes an argument, side effect, or default of
`DeliveryCompiler`.

## Public Contract

```python
export = OpenSpecExporter(store).export(
    round_id="round-123",
    technical_package=package,
    openspec_root=repository_root / "openspec",
    change_name="add-isolated-worker",
    draft=False,
)
```

The explicit call writes a new, non-overwriting directory at:

```text
<openspec_root>/changes/<change_name>/
  proposal.md
  design.md
  tasks.md
  specs/<decision-slot-id>/spec.md
  research-tree-export.json
```

`OpenSpecExport` returns the exact source package reference, the emitted paths,
and whether the caller selected draft mode. It does not append an unrelated
default delivery artifact or mutate the package, its Decision Ledger entries,
or repository input.

## Source And Completeness Rules

- The supplied package must be the exact persisted
  `technical-research-package` revision in the requested round and pass the
  RT-007 package validator.
- Normal export requires a nonempty Blueprint Closure and implementation plan,
  no `missing` or `blocked` closure item, and passing intent alignment,
  decision closure, traceability, repository fit (or `not_applicable`), and
  implementation-readiness gates.
- Operational quality may be explicitly `deferred` because its recorded
  handoff/next action remains part of the export; a failure is rejected.
- `draft=True` deliberately relaxes the readiness/closure gate, but every
  emitted Markdown document begins with a draft warning and carries the exact
  blockers. It never repairs or invents absent decisions.
- Validation occurs before any output directory is created. A target change
  directory must not already exist, preventing accidental overwrite.

## Projection Rules

| Package material | OpenSpec projection |
| --- | --- |
| scope, intent, capabilities, baseline, impact | `proposal.md` |
| selected/conditional decision, consequence, validation, trace refs | `specs/<slot>/spec.md` as an `ADDED` requirement and scenario |
| design groups, decisions, alternatives, risks, migration/operational handoff, repository touchpoints | `design.md` |
| contiguous implementation plan order, dependencies, touchpoints, validation, rollback | unchecked checklist items in `tasks.md` |
| exact package and upstream artifact references, baseline revision/facts/anchors | `research-tree-export.json` and source-reference sections |

Repository-backed packages state the observed baseline revision, anchors, facts,
and touched paths as a delta. Greenfield packages state that no repository
baseline was selected. Where the package has no migration decision, the design
says so rather than making one up.

## Non-goals

- No automatic OpenSpec export from delivery compilation.
- No requirement generation beyond selected/conditional package decisions.
- No repository scan, source acquisition, or in-place modification of the
  supplied repository.
- No overwrite/merge behavior for a pre-existing OpenSpec change directory.

## Test-First Acceptance Cases

| Case | Expected result |
| --- | --- |
| complete repository-backed package | explicit call emits proposal, delta specs, design, ordered tasks, and a provenance manifest with observed baseline/touchpoints |
| normal delivery without export call | creates no OpenSpec directory or files |
| incomplete package, normal mode | raises before creating an output directory |
| incomplete package, explicit draft | emits documents marked `DRAFT` with exact closure/readiness blockers |
| existing change directory | rejects rather than overwriting any existing file |
| forged/unpersisted package revision | rejects before output because the source cannot be resolved exactly in the `RunStore` |
| direct-storage section drift | rejects a decision record that contradicts its Blueprint Closure before output |
