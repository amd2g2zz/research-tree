# RT-001 需求理解

## 本轮目标

为新的 `research-tree` 产品建立一个最小、可本地验证的运行时基础：每个
研究轮次都拥有独立、可重建的状态与不可变的工件谱系。这个基础必须服务于
后续的 Context Pack、Intent Model、Strategy、Decision Ledger 和交付物，
但不提前实现它们的业务规则。

## 已确认的需求

| 需求 | 可观察行为 |
| --- | --- |
| 显式存储边界 | 调用者必须传入 `RunStore(root)`；运行时不读取或写入全局 workspace。 |
| 轮次隔离 | 两个不同 round 在同一个 store 中可独立创建、写入和读取，互不覆盖。 |
| 不可变工件 | 每次写入生成一个新的 revision；旧 revision 的字节内容和摘要不变。 |
| 可重建 | 新建 `RunStore(root)` 后可由 round 元数据、artifact 文件和 lineage event 重建同一视图。 |
| 谱系 | round 可指向 parent round，artifact 可指向已存在的 parent artifact revision。 |
| 受控边界 | round id 和 artifact id 不能成为路径穿越入口；持久化边界拒绝非 JSON payload。 |
| 最小可用入口 | 提供 `create-round` 与 `show-round` CLI，以及可由后续模块调用的 Python API。 |

## 与产品契约的关系

`PRODUCT.md` 要求 run-scoped storage、immutable lineage，且明确禁止重新引入
旧的全局 `RESEARCH_WORKSPACE/research_state.json` 状态机。本轮只实现该通用
存储层。`references/product-contracts.md` 中的 Round、Intent Model、Working
Brief、Finding Pack、Decision Ledger 等内容将作为之后写入的、带 `kind` 的
artifact payload；RT-001 不解释这些 payload 的领域字段。

## 非目标

- 不恢复 recursive evidence-DAG、强制 intent gate 或 frozen-report 工作流。
- 不实现 intake、intent、strategy、research、convergence、delivery 或
  verification 的领域行为。
- 不提供服务端、UI、远程存储、跨进程协同编辑或通用迁移框架。
- 不自动生成 OpenSpec。

## 验收映射

本轮通过两组隔离测试、revision 不变性测试、重载/谱系测试、输入验证测试和
CLI 冒烟测试证明上述行为；从干净 checkout 使用受锁定依赖的测试命令运行。

# RT-002 需求理解

## 本轮目标

把任意数量的请求者材料登记为可追溯的 Input Ledger 条目，并在不执行仓库代码、
不越过文件边界的前提下建立 repository baseline。材料可以独立进入 round，也可
以 Context Bundle 的形式一起进入；bundle 只保留交付时的分组，不能制造一个
虚构的统一 brief。

## 已确认的需求

| 需求 | 可观察行为 |
| --- | --- |
| 独立材料登记 | 一句 brief、article、note、draft 和 repository 都能形成独立的、带 origin、revision、read scope、role 和 round 使用记录的 ledger artifact。 |
| Bundle 不抹平差异 | bundle 保存成员 id 与其精确 artifact revision；成员的内容、role、origin 和 revision 保持独立。 |
| 仓库事实优先 | repository input 生成 read-only baseline，至少包含可解析的路径/符号 anchor，以及 source、interface、dependency、test、deployment 和 change-surface 事实。 |
| 安全 intake | 不读取 secret 命名文件、二进制、超限文件、默认无关大目录或任何 symlink 内容；仓库外路径和外链 symlink 必须被拒绝或记录。 |
| 局部失败 | 一个不可读或越界材料只产生带 reason 的 unreadable 记录，不阻断同一 repository 或 round 中的其他安全材料。 |
| 不可变性 | 重新登记同一 input id 只产生新 artifact revision；bundle 使用精确 member refs，不能静默改指向新内容。 |

## 非目标

- 不从材料推断 Intent Model、架构或商业结论。
- 不请求或采集外部网页、运行测试、构建命令或任何仓库代码。
- 不支持远程 repository clone、全文语义解析、秘密内容识别或跨 round 复用策略；
  后者由后续 feedback/lineage 工作处理。

## 验收映射

测试必须覆盖独立 text intake、冲突成员 bundle、真实 Git fixture 的 revision 和
reconnaissance、变更后的重新登记、scope 越界、secret/binary/size/directory/symlink
边界，以及局部失败后仍可取得安全 baseline。所有 fixture 都只允许向 `RunStore`
写入；输入 repository 的工作树必须保持不变。

## 2026-07-31 14:20

## 需求概述

RT-003 将 RT-002 的异构 Context Bundle 转化为可追溯、可修订的 Intent Model 和
Working Brief。它服务于后续技术研究策略，但不把推断伪装成用户原话，也不把正常
歧义变成必须等待用户回答的流程闸门。

## 功能需求

### P0 - 必须实现

- [x] 从精确的 input/bundle artifact revision 编译 Intent Model，区分 literal signal 和 inferred hypothesis。
- [x] 保留一个 leading interpretation 与所有设计后果显著的 viable alternative，并记录其锚点、置信度、后果和验证路径。
- [x] 从 Intent Model 编译 Working Brief，保留输入角色、冲突、约束、假设和默认双交付目标。
- [x] 仅在不可逆、高影响且现有材料无法排序的歧义上给出非阻塞 Question Recommendation；brief 仍需生成。
- [x] 通过 RunStore 追加 immutable revision，不能覆盖既有 Intent Model 或 Working Brief。

## 边界与约束

- 不实现 LLM、网页对齐研究、Strategy、Decision Map、feedback lineage 或 OpenSpec exporter。
- 分析结果由可注入的确定性 adapter 提供；本 issue 只校验、锚定和编译它。
- 不创建等待用户输入的运行状态。

## 验收标准

- Given 冲突材料，When 编译 Intent Model，Then literal signals 和 leading/viable interpretations 独立可追溯。
- Given 缺失 input anchor 或未标注 inference，When 编译，Then 拒绝且不留下 artifact revision。
- Given 部分未解决歧义，When 编译 Brief，Then 明确保留 assumption/alternative 并继续；仅满足三项例外条件时返回 recommendation。
- Given 已持久化的 model/brief，When 重新打开 RunStore，Then revision 和 parent refs 保持不变。

## 2026-07-31 RT-004

## 需求概述

将当前 Working Brief 编译为 Blueprint Target 和 Decision Map。它是实施前必须关闭的
技术决策集合，而不是需求问卷或报告目录。每个 Decision Slot 必须明确其意图归属、
仓库落点或绿地假设、替代方案、验证方式与可回退路径。

## 功能需求

### P0 - 必须实现

- [x] 从已持久化的 Working Brief 和其 Intent Model revision 编译不可变的 Blueprint Target。
- [x] 校验每个 Decision Slot 的问题、意图假设、约束、替代方案、仓库 touchpoint、依赖、证据标准、验证、closure rule、状态和 fallback。
- [x] 对 P0 slot 强制意图归属、至少两个候选方案、有限研究需求或有效 closure，以及验证与 fallback。
- [x] 对 repository-backed Brief 校验 path/symbol touchpoint；没有 repository 时强制显式 greenfield assumption。
- [x] 支持 `add`、`split`、`merge`、`remove`、`reprioritize` 的 append-only target revision，并记录理由和来源/目标 slot。

## 非目标

- 不产生 Work Item、不调度研究、不生成 Finding Pack 或 Decision Ledger。
- 不把 Decision Map 变成对用户的强制澄清表。

## 验收标准

- Given repository baseline，When 编译 target，Then 每个 concrete touchpoint 都能解析到已记录的 path/symbol anchor。
- Given P0 缺失意图归属、替代方案、研究边界、验证或 fallback，When 编译，Then 写入前以可行动错误拒绝。
- Given target revision，When 添加、拆分、合并、删除或重新排序 slot，Then 新 revision 记录变更理由并保留前一 revision ref。
- Given 无效依赖、循环依赖或未建模的 Intent Model/Brief，When 编译，Then 不写入部分 artifact。

## 2026-07-31 RT-005

## 需求概述

将 Blueprint Target 中仍需研究的 Decision Slot 变成边界明确的 Work Item。Work Item 是
产生 Finding Pack 的任务单位，不是报告章节，也不表示底层决策已经关闭。

## 功能需求

### P0 - 必须实现

- [x] 每个 Work Item 只绑定一个存在的 Decision Slot，并携带该 slot 的意图假设、可改变决策的原因、scope/exclusions、方法、预算、依赖、完成规则和 Finding Pack 契约。
- [x] 根据 Blueprint Target 以 `serial` 或 `dependency_respecting` 方式确定性地产生 active slot 的 Work Item 图。
- [x] 拒绝缺失、已关闭或与当前 target 无关的 slot；如必须保留例外，要求显式 exception reason。
- [x] 通过追加 revision 提供带原因的 `cancelled` / `deferred` 状态，而不修改旧 Work Item。

## 非目标

- 不执行 Web 搜索、仓库分析、实验或自适应并行调度。
- 不把 Work Item 完成状态作为 Decision Slot closure 的替代。

## 验收标准

- Given 同一 target 和 ID 映射，When planner 重复运行，Then 输出 slot 顺序、依赖和 payload 均确定。
- Given P0/P1 active slot，When 规划，Then Work Item 有受限问题、预算、Finding Pack completion contract 和指向 target 的精确 parent ref。
- Given 缺失/closed slot，When 无 exception 编译，Then 不留下 artifact；有 exception 时必须记录原因。
- Given 目标移除或不再需要一个 slot，When lifecycle 取消或延期任务，Then 产生可追溯的新 revision。

## 2026-07-31 RT-006

## 需求概述

以 Finding Pack 和 Decision Ledger 取代散落 worker 报告作为研究收敛点。Finding Pack 只
记录可审查的观察、锚点、适用范围、限制与对候选方案的影响；Decision Ledger 才记录当前
技术选择及其设计和实施后果。

## 功能需求

### P0 - 必须实现

- [x] 从精确 Work Item 注入不可变 Finding Pack，拒绝纯 source list 或无原子 observation 的报告。
- [x] 每条 observation 记录 anchor、适用范围、confidence 和 limitation；option effect 必须指向 slot 的候选方案。
- [x] 从一个或多个 Finding Pack 收敛 versioned Decision Ledger entry，包含 status、选择、替代、设计后果、仓库落点、验证 oracle、fallback、reversal condition 和 change tasks。
- [x] 对 P0 selected/conditional 决策强制从 Finding Pack anchors 到设计后果、change task 和 acceptance oracle 的追溯路径；blocked/deferred 必须显式 fallback。
- [x] 证据冲突和决策反转都通过新增 artifact revision 保留历史。

## 非目标

- 不实现生产 source acquisition、网页抓取或源质量自动判定。
- 不以源数量、阅读量或报告篇幅作为收敛指标。

## 验收标准

- Given 两个相反的 Finding Pack，When 收敛 conditional Decision，Then 两个 finding ref 都可追溯且没有被合并成虚构共识。
- Given 缺少 alternatives、reversal condition、atomic observations 或 P0 change task，When 编译，Then 拒绝且没有部分 artifact。
- Given 新 evidence 改变选择，When 更新 Ledger，Then 旧 decision/finding revision 保持原样，新 revision 指向前一决策。

## 2026-07-31 RT-010

## 需求概述

RT-010 在同一研究轮次内对已定义的 Work Item 组合进行可重建调度。它根据决策影响、
不确定性、下游杠杆、不可逆性、预期信息增益、成本和重复风险决定优先顺序，并在证据
冲突、原型失败、仓库事实推翻假设、新 P0 决策或预算饱和时追加新的 portfolio revision。

## 功能需求

### P1 - 必须实现

- [x] 从精确的 Work Item revision 重建独立于 provenance/decision 图的本地依赖 DAG。
- [x] 对每个可调度工作公开整数评分分量、ready portfolio、dispatch/defer/cancel/wait 理由和预算账目。
- [x] 只把真正无依赖关系且未重复的 Work Item 放入同一并行 batch。
- [x] 显式处理循环、重复、未知依赖和预算耗尽；无效图在写入 portfolio 前拒绝。
- [x] 将重排原因、受影响 Work Item 和精确证据 refs 作为新的不可变 revision 保存，而不创建新的用户轮次。

## 非目标

- 不恢复全局递归下降、证据 DAG 或伪装成最优策略的学习算法。
- 不执行 Work Item、不修改 Decision Ledger，也不把常规同轮重排变成用户澄清问题。

## 验收标准

- Given 相同 Work Item、评分与预算，When 在干净 store 重建，Then DAG、分数、ready 顺序与批次完全一致。
- Given 依赖或预算限制，When 调度，Then 只派发独立任务，并为其余任务保留明确原因。
- Given 证据事件改变优先级，When 重排，Then 新 portfolio 指向旧 revision 并保留事件来源。

## 2026-07-31 RT-007

## 需求概述

RT-007 将已经收敛的结构化 Intent Model、Working Brief、Repository Baseline、Blueprint
Target、Decision Ledger 和 readiness 数据编译为两份不同的交付物：实现 agent 使用的
Technical Research Package，以及请求者阅读的 Human Brief。它不把 worker 的自由文本报告
拼接成文档，也不因为生成交付物而默认创建 OpenSpec。

## 功能需求

### P0 - 必须实现

- [x] 仅从精确持久化的结构化 artifacts 编译交付；输出要保留 Brief、Intent Model、
  Target、input baseline 和 Decision Ledger revision 的完整 parent refs。
- [x] Technical Research Package 必须列出 scope、intent basis、repository baseline、
  Blueprint Closure、决策/替代方案、接口和变更边界、实施任务、oracle、fallback、
  reversal condition、风险和 readiness。
- [x] 每个 P0 selected/conditional decision 必须能从 package 独立定位到 intent、
  anchors、touchpoints、validation、rollback/fallback 和实施任务。
- [x] 没有 Decision Ledger entry 的 slot 必须以 "missing" closure 显式呈现，不能在 prose
  中被掩盖。
- [x] Human Brief 必须独立可读，只说明理解、方向、重要取舍、近期里程碑和风险，不能成为
  Technical Package 的缩短拷贝。
- [x] 对 implementation-facing 必填字段做 schema/template 校验，任何无效输入均不能留下
  部分 package 或 brief artifact。

## 非目标

- 不生成 OpenSpec、不接收 worker prose，也不执行深度研究、source acquisition 或 readiness
  verification。
- 不修改已有的 Intent/Brief/Decision Ledger/input artifact。

## 验收标准

- Given 一组完整的 P0 Decision Ledger entries，When 编译，Then 实现 agent 仅阅读 Technical
  Package 就能定位 change surface、接口、acceptance oracle、fallback 和 reversal condition。
- Given 一个未闭合的 Decision Slot，When 编译，Then Package 明示 "missing" 和后续闭环路径。
- Given 缺少 P0 实施字段或给出 stale ledger revision，When 编译，Then 两个 delivery artifact
  均不被写入。
- Given Human Brief，When 不读取 Technical Package，Then 仍能理解推荐方向、重要取舍和风险。
