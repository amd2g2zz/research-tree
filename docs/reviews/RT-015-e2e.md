# RT-015: Integrated E2E Audit

## Scope

This audit checks the rebuilt product spine rather than a single artifact
compiler. The required path is heterogeneous input and repository baseline to
Intent Model/Working Brief, Blueprint Target, bounded work, findings, decision
ledger, separate Technical Research Package and Human Brief, readiness, then a
separate implementation/evaluation handoff.

## Executed Scenario

`tests/test_e2e_blueprint.py` starts with the repository-backed delivery
fixture and completes the following sequence in one immutable round:

1. Compiles a traceable Technical Research Package and a separate Human Brief.
2. Verifies the package at `high` risk through a fake evaluator-managed
   isolated adapter. The request excludes live repository roots and records
   build, hidden acceptance, and regression results.
3. Runs a separate implementation evaluation. The runner request excludes the
   opaque hidden-oracle id; the record retains structural quality, independent
   outcomes, cost, clarification burden, and a named simpler baseline.
4. Calls `OpenSpecExporter` explicitly and verifies that no OpenSpec directory
   exists before that call.
5. Leaves assurance adapter selection absent without blocking the P0 handoff.

The fake adapters are intentional: they verify product contracts and data
boundaries deterministically. Actual sandbox provisioning, source acquisition,
and hidden acceptance execution remain caller/evaluator-owned adapters.

## Guardrail Review

- No delivery path calls `OpenSpecExporter`; it remains an explicit downstream
  operation.
- Feedback target changes use `FeedbackRoundService.start_successor`; routine
  replanning is retained separately in the same round.
- Research strategies fix routine unknowns to recorded assumptions and
  validation, and reserve user questions for non-recoverable decisions.
- Assurance selection is optional and decision-local. It does not add a global
  evidence DAG, scheduler gate, or fixed report workflow.
- RT-011 never launches repository code from the host process and sanitizes
  the isolated verification request.

## Evidence

The final integrated validation command is:

```powershell
uv run python -m pytest -q
```

The suite includes the cross-module smoke test together with focused tests for
input safety, intent/brief lineage, decision closure, readiness, feedback
lineage, explicit OpenSpec export, risk verification, evaluation, and optional
assurance adapters.

## Remaining Operational Responsibilities

- Production isolated-verification and evaluation adapters must provision the
  real sandbox, secret policy, and hidden acceptance environment.
- Evaluators must retain time-split patches/discussions/oracles outside the
  public case manifest and implementation request.
- Strategy selection remains an agent decision informed by the structured
  intent/brief; the runtime intentionally does not infer it from keywords.
