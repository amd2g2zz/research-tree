# research-tree v2.0 产品宪章（Product Charter）

版本 v2.1 · 2026-10-28 · 状态：定稿待评审（v2.1：页面逻辑定稿——项目首页/侧栏研究树/hub 对话（原型验证回写，见 03）；v2.0：**git 语义重构**——研究 = 主线 + 无数支线；对象模型 Project/Task/Version/Fork/Draft；三步走产品流程；chat 优先；分解六要素可视化；产物默认不冻结、冻结即提交（摘要+commit hash）；版本+1 继续研究；任意版本 fork 可跟踪；草稿不可跟踪；默认展示主分支最新）

## 1. 产品定义

**research-tree 是研究台：接住任何清晰度的想法，逐个补上关键缺口，做一份诚实的、带反证的研究——而研究本身像 git 一样生长：一条主线，无数支线，每个版本可追溯、可分叉。**

名字的由来：research **tree**。研究的生命周期不是一次性管道，而是一棵树——主干是持续深化的研究线，任何已提交版本都可以分叉出支线（换个约束重研、补充新证据、假设推演），图谱全程可跟踪。

## 2. 三步走（产品主流程）

### 第 1 步 · 建立项目
用户给出**项目简单描述 + 相关附件**（图片、文档、表格、PPT 等）。系统建立 project-id（**用户不可见**，项目唯一标识符）。一个项目 = 一个研究主题。附件进入任务背景要素池。

### 第 2 步 · 对话与分解
- 进入**默认 chat 界面**，分配 task-id（**一个 project-id 对应多个 task-id**；task-id 一经分配固定不变）。
- 用户自由对话（倾倒想法、澄清、追加）。用户觉得聊得差不多了，点**确认**。
- 系统把对话**分解**为：需求、条件约束、任务背景、用户意图、拒绝点、难点等要素——**分解得越充分越好**（详见 01 分解算法）。每条要素必须可溯源到原句/附件。
- 分解结果**可视化**呈现（见 03-journey §分解可视化）。用户确认后才启动 research（**默认版本 v0**）。研究不是黑箱起跑。

### 第 3 步 · 研究与版本（git 语义）
| 动作 | 语义 |
|---|---|
| 研究结束 | 产物**默认不冻结**：可对研究产物或节点进行**删除**；回到 chat 可继续讨论 |
| **冻结并提交** | 当前任务被冻结不能再动 → 自动写**研究摘要消息 + commit hash**，版本落库（v0, v1, …） |
| **继续研究 / 补充** | agent **基于已有研究**与用户重新对齐 → 版本 +1（新 draft → 冻结 → 提交） |
| **分叉（fork）** | **从哪个版本分叉，就相当于从哪个版本 fork 一个 research**，图谱里全程可跟踪；分叉产生新 task-id |
| 草稿 | 不提交就存在草稿里，**无法被跟踪**（不入图谱、无 hash） |
| 展示规则 | 默认只展示**主分支上的最新版本**，除非用户主动切换 |

## 3. 对象模型（git 语义）

```
Project (project-id*, 隐匿; 一个研究主题; 附件集)
  └─ Task (task-id, 固定不变; 一次研究线; 主分支或分叉产生)
       ├─ Version v0..vN (committed: 摘要消息 + commit hash; 不可变, 可分叉)
       └─ Draft (未冻结的工作态; 不可跟踪, 不入图谱)
```

- **Project : Task = 1 : N**；**Task : Version = 1 : N**（同一线上的递进版本）。
- Fork 边 = (task_id, version) → 新 task_id，记录在图谱中，双向可追溯（"我从哪来"与"我派生了谁"）。
- 结局四态不变，附着在**版本**上：GO / NO-GO / PARK / REFRAMED 全部是成功（GO 交底稿、NO-GO 墓地+复活条件、PARK 冻结 brief、REFRAMED 继承账本）。

## 4. 设计公理（不可违反）

1. **不判定用户，只处理请求**——缺口填补机制；机制可分类话语的语义类型，永不分类说话人。
2. **反证攻击主张，不攻击人**——敢劝退是结构性稀缺。
3. **rt 负责认识论，不负责承诺**——真伪与可行性归 rt；成本估算/排期归下游。底稿 schema 是与下游的唯一接缝。
4. **概率不掺偏好，决策才用偏好**——偏好防火墙。
5. **便宜的死法优先**——错误主张死在对话快验 < 早终止 < 最终报告。
6. **草稿可变，提交不可变**（v2.0 新增）——冻结前一切可删可改；冻结即 append-only，任何"修改历史"都是一次新提交。研究历史的完整性靠不可变版本保证。
7. **分叉即继承**（v2.0 新增）——fork 继承源版本的账本、证据与结论；从哪个版本分叉，图谱就能追溯到哪个版本。

## 5. 差异化定位（不变）

搜索给你事实，Deep Research 给你综述，grill-me 给你清醒——**rt 给你裁决，且研究是一棵可生长、可追溯、可分叉的树**（Deep Research 类产品每次都是一次性管道，研究无法迭代、无法继承、无法分叉——这是 v2.0 的结构性差异）。

## 6. 画布与信任面（保留 v1.1，叠加版本维度）

画布 = 信任面：类型化节点 + 带标签边 + 抽屉三层下钻（节点→详情→原始会话/证据）+ console 尾流 + minimap + 时间轴回放；写操作仅五门（暂停恢复/杀阶段改道/park/裁决确认/追加信息）。v2.0 增加版本维度：版本时间线与分叉图谱是画布的一部分。

## 7. 验证假设

| # | 假设 | 实验与度量 |
|---|---|---|
| H1 | 接住模糊：rt 吃下 raw 想法，用户 prompt 功夫 << Deep Research | 同想法双跑，数用户修改轮次 |
| H2 | 敢劝退：rt 报告的"不做/放弃"论述质量显著高于 Deep Research | 第三方盲评 |
| H3 | 底稿直通：rt 底稿喂实现 agent，启动质量 >> essay | 澄清问题数/方向偏差数 |
| H4 | 引用可核验：证据核验抽检通过率 ≥95% | 随机抽样人工溯源 |
| H5 | 早终止省钱：make-or-break 中途死亡案例的预算节省 ≥50% | 对照全量跑完的成本 |
| H6 | 12h 无人值守可信：过夜跑后画布可完整回放 | 过夜跑实测 |
| H7 | 版本即复利：用户在 v0 基础上继续研究/分叉的比例 ≥30%（v2.0 新增） | 版本/分叉操作遥测 |
