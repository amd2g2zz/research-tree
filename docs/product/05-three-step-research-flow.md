# 三步研究流（对话 → 思维导图确认 → 调研画布）— WebUI v3 设计规格

版本 v1 · 2026-11-03 · 状态：用户口述定稿（本文件是其实现规格）· 上位文档：00 宪章 / 01 算法 / 03 旅程

## 0. 产品定位约束

rt 为**复杂 research**而生：把一个想法整理成**完整可落地的方案**。要解决的问题普遍**复杂、长时间跑**（例：「我想开个数据标注公司」——太虚，不可能直接落地）。因此产品流必须是三层递进的**虚实转换**：虚想法 → 对齐澄清 → 结构化确认 → 长时程调研 → 可落地交付物。

## 1. Chat 阶段（已有，需打破「墙」）

**现状**：A1 策略引擎侧已内置（四分路由、歧视性提问、约束溯源问询、收敛判定 C1-C5、发散检测）——但 WebUI 只把路由结果作为回执展示，**agent 不说话**，用户对着一堵墙。

**目标行为**：
1. **回应**：每条用户话术，agent 给出实质回应（复述理解、指出缺口、表态下一步），不是路由回执。
2. **主动提问**：agent 主动提问消除歧义（用 A1 的歧视性提问策略：部署事实 vs 主观估计；缺失的 kill 条件；预算/范围）。
3. **前期侦查**：为把问题变清晰，agent 可做**简单实验与资料搜索**（经 DataSourceProvider 端口：anysearch 搜索、agent-browser 渲染页），侦查结果作为对话内容回填。
4. **出口**：用户确认「没问题了，可以开始调研」→ 进入确认阶段。

**实现要点**：server 新增 `chat.turn`——转写+槽位+账本状态 → pi 会话（结构化 JSON 输出：reply / questions[] / recon?）→ 侦查经 provider 端口执行并回填 → 全部落 chat_messages（reply 也是数据）。分类（#651）并行保留。

## 2. 确认阶段（独立页面：思维导图）

**行为**：根据 chat context 把聊天内容转化为**思维导图**：
- **核心主题** = context 中要解决的核心问题（LLM 提炼，用户可改）。
- **二级主题至少**：限制条件、任务背景、调研目标——**不确定、可更多**（如拒绝点、难点、假设、验收标准）。
- 每个二级主题向下分解，**最多 5 级**。
- 用户可直接**在导图上编辑**（增删改节点），或**回退到 chat 阶段**继续聊。
- 用户**确认**后进入调研阶段（导图随版本落盘，成为调研的输入结构）。

**实现要点**：`decompose.toMindMap`（pi 会话：转写+槽位+账本 → 树 JSON；核心问题+二级主题+逐层分解，≤5 级，每节点带 quote 溯源）；存储复用 decompositions surface（结构字段=树）；前端独立页面渲染可编辑树（缩进树 v1，节点增删改+子级展开）；「回退 chat」保留一切状态。

## 3. 调研阶段（独立画布页面：动态 DAG + subagent）

**行为**（对照截图形态）：
- 根据思维导图进行 **stage 拆分**：stage **无上限**，但**绝不一口气拆完**——**最小规划 + DAG**，按任务动态分批（参考 Spark 的 lazy 调度：跑完一批、检视产出、再规划下一批）。
- 不同 **subagent 分配到不同节点**执行（pi-subagents keyed 派发，#552 端口）。
- 每个 stage 跑完**循环检视**：产出是否满足继续 work 的条件；直到满足**开环条件**（叶子节点「结论明确」/ EVSI 饱和 / 预算尽）才停止规划。
- **节点产出**：点击底部**抽屉**查看产物预览（artifacts surface）。
- **过程可视化**（对照截图）：画布节点卡片（状态徽章「结论明确」等、进度百分比、预算位）、虚线边带标签（归因分析/背景等关系）、左侧统计条（BURN tokens / SOURCES / REMAINING points / TIME）、底部 **Console 终端流**（工具调用逐行滚动）、右下 **minimap**。

**实现要点**：
- `research.planNext`（增量规划器：已完成产出+导图开枝 → pi 提议下一批最小 stage + DAG 边；禁止一次拆完——单批 ≤3 个新节点）；
- 派发循环：scheduler.tick → subagent 派发（pi dispatch）→ stage 产出（artifacts upsert）→ **planNext 循环**直到开环/预算；
- 画布前端：节点卡 DAG 布局（状态徽章+进度+预算）、边标签、统计条（burn/sources/remaining/time）、Console 流（已有 #572 事件流复用）、产物抽屉（artifacts 预览）、minimap；
- 长时程：12h 硬帽 + 无人值守（#569）承担过夜跑。

## 4. 与既有引擎的映射（不推翻，重排表面）

| 三步 | 引擎既有 | 本规格新增 |
|---|---|---|
| Chat | A1 全套策略（内置）| chat.turn 对话回路 + 侦查执行 |
| 确认 | A0 六要素 + 充分性 checklist | toMindMap 树转换 + 可编辑导图页 |
| 调研 | 调度器 tick/失败重试/并行帽 + #569 无人值守 + artifacts surface | planNext 增量规划 + subagent 派发循环 + 画布可视化 |

六要素/checklist/kill 图/EVSI/双席/实验层等既有机械规则**全部保留**——思维导图是它们的**用户面结构**，不是替代。

## 5. 失败信号

agent 回应空洞（复述≠回应）；导图节点无 quote 溯源；规划器一口气拆完；画布不可回放（#572 确定性投影必须保持）；侦查未落 provider 审计。
