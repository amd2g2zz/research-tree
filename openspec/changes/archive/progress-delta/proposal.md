# Proposal: progress-delta

## Why

issue #329: senior users lose patience when long runs narrate known context,
low-level parameter errors, source failures, timeouts, patch failures, and
fallback attempts.  Context accounting measures source acquisition, but
user-visible progress is generated by host/model behavior with no canonical
delta-typed projection.

## What Changes

1. NEW `src/research_tree/progress_delta.py`:
   - `ProgressDelta`: tuple-fields for new_evidence / changed_model /
     changed_decision / changed_phase / new_blocker / changed_authority /
     changed_next_action (the 7 canonical delta kinds).
   - `ProjectedFailureGroup`: aggregated failures (kind, severity, count,
     receipt_refs, first_seen/last_seen).
   - `ProjectedProgress`: compact user-visible projection with deltas/phase/
     internal_failures/decision_relevant_failures + Mapping-friendly
     `__getitem__`.
   - `project_delta(delta) -> ProjectedProgress`: pure projection.
   - `aggregate_failures(...) -> ProjectedFailureGroup`: collapse repeated
     same-kind failures with count + receipt refs.
2. Pure functions, no side effects — the canonical consumer surfaces
   projection through `coordinator.self_state.lineage` (already added by #324).

## Impact

- src/research_tree/progress_delta.py (new) — no behavior change to existing
  modules; tests prove the projection rules.
- Behavior for callers who don't import this module is byte-identical.
