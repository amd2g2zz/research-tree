# Proposal: enforce-phase-discipline

## Why

Issue #492 (confirmed): the designed phase discipline is not enforced by the
runtime. (a) After compilation the run can keep mutating the strategy via
"internal successor revision" without returning the user to realignment — the
SKILL prose explicitly authorizes it; (b) when the user interrupts during
research there is no enforced two-option re-entry protocol (back-to-alignment
vs. supplement-in-research); (c) nothing mechanically rejects chatty
interaction once research has started. The pipeline has drifted from
"alignment → strategy optimization → compile → research" into an endless
interactive research loop.

## What Changes

1. `tree_state.py`: explicit run `phase` discriminator
   (intake / alignment / compiled / research / validation / delivery) on the
   research-tree state payload. Transitions are gated: a payload claiming an
   illegal phase transition is rejected by the existing schema validation
   (`validate_tree_state_payload` + `CanonicalResearchTreeStateService.transition`).
   A tree is born `compiled` (revision zero exists only after the confirmed
   handoff compiles).
2. `tree_state.py`: post-compile realignment gate. The payload may carry the
   confirmed projection's `strategy_authority_fingerprint` (mechanism from
   PR #450). A transition that changes that fingerprint is rejected unless it
   is the recompile edge out of re-entered `alignment` AND carries a
   `realignment` record binding the new fingerprint to a fresh user
   confirmation digest. Any other strategy-material change is rejected.
3. `lifecycle_hook.py`: two-option re-entry protocol. When the run phase is
   `research`, every user prompt is resolved to exactly one protocol path —
   `reopen_alignment` (re-align to user confirmation, recompile) or
   `supplemental_evidence` (record and stay in research) — plus `status_echo`
   as the only acceptable status interaction; everything else (including
   chatty conversational drift) is refused with a named code. The resolution
   is recorded on the signal record and routed to the run's events surface.
   Phase source (fail-open, standalone-hook safe): explicit argument,
   `RESEARCH_TREE_RUN_PHASE`, or the run manifest's `phase` key.
4. Prompt layer (canonical sources only): `skill-src/SKILL.template.md` and
   `skill-src/hermes-SKILL.template.md` replace the "create a successor
   revision internally and continue without another approval" clause with the
   realignment requirement (进入编译阶段后不可改，改就要重新对齐) and the
   two-option re-entry protocol; `packages/**` regenerated by
   `scripts/build_skill_packages.py`.
5. Tests: `tests/test_tree_state_phase_discipline.py` and
   `tests/test_lifecycle_hook_reentry.py` cover every illegal phase
   transition, the realignment gate, and both protocol paths plus refusals.

## Capabilities

### New Capabilities

- `run-phase-discipline`: gated run-phase transitions on the research-tree
  state, post-compile realignment requirement, and the research-phase
  two-option re-entry protocol.

### Modified Capabilities

- None.

## Impact

- src/research_tree/tree_state.py: `validate_tree_state_payload` gains three
  optional payload keys and their validation; `initialize`/`transition` gain
  the phase + fingerprint gates (GitNexus impact: LOW risk; callers
  `_normalized_state`, `latest`, and the recursive-search coordinator).
- src/research_tree/lifecycle_hook.py: UserPromptSubmit signal path gains the
  re-entry resolution and one routed record type (GitNexus impact: LOW risk;
  caller `observe` → `main`).
- skill-src/*.template.md + regenerated packages/**: prose only.
- No changes to alignment_graph.py, decision_frame.py, search_portfolio.py,
  cross_comparison.py, recursive_search.py, coordinator.py, or cli.py.
